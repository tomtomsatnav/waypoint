autopilot and E13's single session (copied in unchanged).

Caveat: the owner had already played E13's single-session game, so this comparison is not fully blind.

stand-in guard freezing every test that existed when a task started, so later tasks could not fix flaky tests written by
earlier workers ("blocked on frozen-file edits"). Spend at 11:00 UTC 11 Nov: $32.32 recorded of $60 (research, planning
and reviews $6.77), plus the unrecorded cost of the killed attempts.

**Reveal: 3101 = E13b's autopilot, 3102 = E13's single session. The owner preferred the autopilot.**

**Reading.** First win for the framework over plain Claude Code on the same brief, after three changes from E13: research
before planning (EXPECTATIONS.md put the mouse camera, which lost E13, on the list with a check), a playable first
milestone, and capped Sonnet reviews (overhead fell from 65% of spend in E13 to 29%). It cost about 7x more and took about
50x longer. Half of the time went on two framework faults, both since fixed or identified: waiting on hanging background
tests, and the guard freezing earlier workers' flaky tests. n = 1, one judge, not fully blind. E13c (research step + one
plain session) is next: it tests whether the research alone gets most of this for a few dollars.

Fix after E13b: the guard now freezes only the acceptance tests the planner and reviewers commit (recorded per run as
`protectedTests`); workers may fix any other test, including flaky ones earlier workers wrote, and are told which tests
are frozen. Runs started before the change keep the old guard.

The research step did not use the web ("Based on knowledge of World of Warcraft, RuneScape/Old School RuneScape, Guild

**Reading.** Across E13, E13b and E13c the one change that consistently helped is writing down, before building, what the
brief leaves unsaid but users take for granted. Given that file, one plain Sonnet session beat the full autopilot at a
fifth of the cost and a fortieth of the time. Milestones, reviews, routing and the guard added cost and failure modes, not
quality, on a project that fits in one long session. They remain untested on work that does not fit (Fable's 10-12 real
tickets). n = 1 per arm, one judge, E13b and E13c not fully blind.

Product consequence: the default becomes `waypoint build` (research, then one plain session, resumed across usage
limits); the autopilot stays for work too big for one session.
