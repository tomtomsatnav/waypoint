In this repository (fenceline), make block mode stop more kinds of Bash writes before they happen. Today the PreToolUse hook can only prevent the writes it reads off a command line (redirections, sed -i, rm, mv, cp, tee, touch, git checkout/restore); the README's Limits section lists what slips through. Teach it to also recognise, as writes: `dd ... of=FILE`; `find DIR ... -delete` and `find DIR ... -exec rm ...` (everything under DIR that find could match counts as a possible target); a command wrapped in `sh -c '...'` or `bash -c "..."` (look inside the quoted command); and `git apply FILE` / `patch ... < FILE` / `patch ... FILE` (the files the patch touches, read from its `+++`/`---` headers). Reads must stay reads: `dd if=FILE of=/elsewhere` reads FILE, `find DIR -name x` without -delete/-exec rm writes nothing, `sh -c 'cat FILE'` only reads. Also add a CLI command `fenceline check "<shell command>"` that prints which fences that command would cross (one line per crossing, naming the fence id) and exits 1 if it crosses any block fence, 0 otherwise. Update the README's Limits section to match. Existing behaviour and the existing tests must keep working.
